论文修改说明

论文题目：面向多模态大模型能力提升的数据合成框架研究

尊敬的老师：

依据您此前对论文提出的修改意见，本人对全文进行了系统性修订与完善。以下分十个方面汇报本次修改的具体内容与改进效果。

一、论文题目调整

依据您"题目应采用'面向......的研究'或'基于......的研究'更规范结构"的建议，论文题目已由原"多模态数据合成框架研究"调整为"面向多模态大模型能力提升的数据合成框架研究"，使题目同时体现研究目标（多模态大模型能力提升）与研究方法（数据合成框架），并与封面、摘要、关键词及全文叙事保持一致。

二、章节耦合性问题——新增"数据能力光谱"主线叙事

针对您指出的"GUI 章和世界知识章之间似乎缺乏逻辑关系，论文整体耦合性较差"的问题，本次修订在第一章绪论中明确提出了"数据能力光谱"这一主线概念。该概念将第三章 GUI（感知极端）、第四章世界知识（推理极端）、第五章 GUI CUA（综合中段）三个研究位置统一到一条主线之中，使三章不再是相互独立的任务，而是数据能力光谱在不同位置上的策略性互补。这一改动从根本上解决了 GUI 与世界知识两章逻辑关联不足的问题。

三、第五章独立实验缺失问题——新增 GUI CUA 端到端验证

针对您"第五章作为统一贡献，缺乏独立的端到端实验，建议补充迁移实验或案例分析"的核心意见，第五章新增了 §5.4 节，将 Auto-Evol 框架实例化到 OSWorld LibreOffice 三个 domain（Calc、Impress、Writer）。具体而言，依托本框架生成 900 条经 8-Gate 全链路过滤的可验证任务，通过指导模型在 Ubuntu 沙箱中 rollout 得到 723 条成功轨迹，进一步单步拆分得到 3 万条训练数据，对 Qwen3VL-Think 模型进行 SFT 训练。实验结果显示，模型在三个 domain 上的 overall accuracy 由 40.8% 提升至 61.4%，绝对增益达 20.6 个百分点。新增表 5-1 完整呈现了训练前后的对比数据。这一独立端到端实验直接回应了您"统一框架是否仅依赖前两章实验进行归纳论证"的疑问。

四、第五章定位模糊问题——明确"双重定位"

针对您"建议更明确地界定第五章的定位为'方法论总结'还是'独立贡献'"的建议，本次修订在第五章本章小结、第六章研究总结、中英文摘要中均显式声明了 Auto-Evol 框架的双重定位。其一是作为对前两章工作的方法论闭合，沉淀横跨两极的共通骨架；其二是作为独立可验证的端到端贡献，在综合中段提供 +20.6 个百分点的量化证据。修订明确指出"两个定位互不替代"，从根本上消除了"方法论或独立贡献"二选一的困境。

五、缺少全文框架图与第三章流程图问题

针对您"论文缺少把不同章节联系的框架图"以及"第三章关于 GUI 数据合成连基本流程图都没有，没有体现出方法的创新性"的批评，本次修订共新增四张关键图表。第一是图 1-1 全文研究架构概览，使用 matplotlib 生成的矢量 PDF，展示数据能力光谱与三章对应关系，让读者在绪论阶段即可建立全文研究蓝图。第二是图 3-1 GUI 数据合成 Pipeline 全景图，将原本仅有文字描述的四阶段闭环流程（结构化初始化、人机协同混合标注、三类 QA 合成、质控与二级去重）完整可视化。第三是表 3-1 GUI 挑战-方法-验证对应表，将三大核心挑战与配套工程难点共五项问题与本文方法及量化验证一一对应。第四是 §3.2 节核心方法概览，将原本散落正文各处的创新点浓缩为可被快速检索的六项关键技术（C1 三类训练任务联合监督、C2 23 类细粒度控件分类学、C3 控件有向关系图谱、C4 三元交互状态向量、C5 AnyRes + 1000 级坐标量化、C6 DMT 双阶段混合微调）。

六、章节衔接问题——自然化处理

针对您"每章开头不要用'本章定位'这种说法，太刻意了，自然一点"的反馈，本次修订删除了原最初版本中各章开头的"本章在全文中的定位"贴标签式声明，转而把光谱定位自然融入各章背景段落的叙述脉络中。读者读完段落后能够自然意识到本章在全文中的位置，不再有被强行标注的生硬感。

七、研究背景论据不足问题——补充关键引用

针对您"研究背景写得非常乱，甚至有点杂乱无章，缺少论据支撑"的意见，本次修订做了两项改进。其一是将研究背景从原五段散文式写法重构为四段结构化论述：问题阐述、研究主张、研究路径（两极论证）、研究架构与贡献预告。其二是补充了 15 处关键论据引用，覆盖数据质量瓶颈（schuhmann2022laion5b、byeon2022coyo、hessel2021clipscore）、人工标注成本（wang2023selfinstruct、mukherjee2023orca）、结构性误差（liu2024seeclick、du2020ppocr、li2023pope、marino2019okvqa、zhang2023multimodalcot）、GUI 任务（deka2017rico、gao2024mobileviews、li2022clay、guicourse2024、liu2025uie2isynth、guiworld2024）、世界知识（marino2019okvqa、schwenk2022aokvqa、chen2023infoseek、chang2022webqa、lewis2020rag、yao2023react）等关键论断。同时新增了 OSWorld（NeurIPS 2024）与 EvoCUA（arXiv 2601.15876）两篇重要 GUI 工作的引用。

八、术语不一致问题——全文统一

针对您"术语需要统一调整，如'正向合成'、'正向构造'、'正向合成框架'在不同位置交替出现"的意见，本次修订在全文范围内完成了 76 处术语统一。具体包括：数据流向方面，将"正向构造"和"正向流"统一为"正向数据流"，将"反向流"和"逆向数据工程"统一为"反向数据工程"，"反向对齐"因语义独立予以保留；流水线方面，全文统一为"Pipeline"（首字母大写）；数据合成方面，将"数据构造框架"统一为"数据合成框架"以与论文题目对齐；质控方面，将"质量控制"统一为"质控"；QA 类型方面，将"三种 QA"统一为"三类 QA"；CUA 命名方面，首次出现使用"GUI 计算机使用智能体（Computer Use Agent, CUA）"完整名称，后续统一简称；极端术语方面，将"精度极端"调整为"感知极端"，使其与 Auto-Evol 框架中"感知/理解/推理"三链路坐标系形成更紧密的概念呼应。

九、标点格式问题——中英标点规范化

针对您"论文中出现大量中英标点混合现象，如逗号是中文、句号是英文"的反馈，本次修订做了三项工作。其一是将全文 92 处中文上下文中的 ASCII 双引号统一转换为中文圆角引号；其二是发现并修正了 fduthesis 模板配置中 fullwidth-stop 选项被设为 mapping 的问题（该配置会把中文句号映射为视觉上接近半角小点的样式），将其调整为 false，使中文句号回归标准的圆圈样式（。）；其三是将表格内的 ASCII 半角括号统一为中文全角括号。修订完成后全文标点已实现 100% 中文规范合规。

十、图片排版问题——清晰度与位置优化

针对您"有些图片如图 4-4 模糊不清；图 5-1 离引用位置太远，排版很随意"的意见，本次修订做了三项调整。其一是图 4-4（case2.png 原始分辨率仅 150×150 像素）的显示宽度由 0.8\linewidth 收缩到 0.35\linewidth，最大限度抑制放大失真。其二是图 4-5（case3.png 640×345）的显示宽度由 0.9\linewidth 收缩到 0.6\linewidth，避免横向拉伸导致的边缘锯齿。其三是把所有图的 placement 浮动指定符由原来的 [t]（仅页顶）改为 [!htbp]（优先此处放置），从源头解决了图 5-1 此前出现的"被推到引用位置后 13 页"的脱节问题。修订后所有图表均紧邻首次引用位置。
