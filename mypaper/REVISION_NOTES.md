# 论文修改意见：GUI CUA 作为"两极综合中段"的论证强化

> **日期**：2026-05-26
> **针对的审稿人意见**：第5章作为论文的"统一贡献"，其有效性完全依赖第3、4章的实验结果进行归纳论证，缺乏独立的端到端实验。建议补充迁移实验或案例分析，或更明确地界定第5章的定位。
> **当前状态**：已加入 GUI CUA 实例化（§5.4）+ 端到端 SFT 实验（§5.4.3，900→723→30k→+20.6pt）
> **新洞察**：GUI CUA 不是 GUI 的延伸，而是「数据能力光谱」上**感知 + 推理 + 状态机**的综合中段场景，能更强地回应审稿人质疑

---

## 一、核心洞察

### 1.1 GUI CUA ≠ 第3章 GUI（Referring/Grounding）

| 维度 | 第3章 GUI<br/>(Mobile UI) | 第4章 世界知识<br/>(WK) | **第5章 GUI CUA<br/>(LibreOffice/OSWorld)** |
|---|---|---|---|
| 任务形态 | 单步定位 | 单步问答 | **多步操作链** |
| 监督形式 | bbox + 文本 | 实体 + CoT | **轨迹 + 中间状态** |
| 感知需求 | ⭐⭐⭐ 像素级 | ⭐ 弱 | ⭐⭐ 控件级 |
| 推理需求 | ⭐ 弱 | ⭐⭐⭐ 多跳 | ⭐⭐⭐ **多步规划** |
| 状态依赖 | ⭐ 静态截图 | ⭐ 无 | ⭐⭐⭐ **动态状态机** |
| 评测形式 | IoU / F1 | F1 / Accuracy | **可执行真实结果比对** |

### 1.2 关键结论

**GUI CUA 处于数据能力光谱的"中段融合区"**：
- 既需要**感知**（看清当前界面控件状态）
- 又需要**推理**（多步操作规划与决策）
- 还需要**状态机理解**（界面状态转移与可执行评测）

这使得 GUI CUA 实例化 **天然就是 Auto-Evol 框架"跨越两极"的迁移验证**，而非"在感知极端这一侧打转"。

（CUA）任务，其完整动作链同时要求模型\textbf{看清当前界面控件
状态（感知）+ 规划多步操作序列（推理）+ 跟踪动态状态转移

### ✏️ 修改②：第5章 §5.4 GUI CUA 实例化 开头（最关键 ⭐）

**位置**：`chapters/chapter3.tex` `\section{Auto-Evol在GUI CUA领域的实例化}` 之后第 1 段

**现状**：直接讲实例化流程，未明确"为什么 CUA 是迁移验证而非延伸"

**建议在 `\section` 后立即加一段「与第3章 GUI 的本质差异」论证**：

```latex
\paragraph{GUI CUA 与第\ref{chap:gui}章 GUI 的本质差异：从感知极端到综合中段}
尽管同属 "GUI" 大类，CUA 任务在监督形式上与第\ref{chap:gui}章
Mobile UI 的 Referring/Grounding 存在本质区别：
\begin{itemize}
  \item \textbf{第\ref{chap:gui}章 GUI（感知极端）}：单步、静态、像素级
        的 Referring/Grounding 监督，模型只需在\textbf{一张截图}上
        完成"指代识别"或"定位落地"，监督粒度为 bbox/OCR/状态向量；
  \item \textbf{第5章 GUI CUA（综合中段）}：\textbf{多步、动态、可
        执行}的操作链监督，模型需要在\textbf{动态变化的桌面环境}中
        完成"感知当前状态 $\rightarrow$ 规划下一步动作 $\rightarrow$
        执行 $\rightarrow$ 跟踪状态转移"的完整闭环，监督粒度为
        \textbf{完整轨迹 + 可执行真实结果比对}。
\end{itemize}
因此，GUI CUA 实例化\textbf{并非第\ref{chap:gui}章 GUI 工作的简单
延伸}，而是 Auto-Evol 框架\textbf{从感知极端跨越到综合中段}的真正
迁移验证：它同时考验框架对\textbf{感知能力（控件状态识别）+ 推理
能力（多步规划）+ 过程性监督（状态机校验）}三类需求的协同
支撑。配合第\ref{chap:gui}章（感知极端）与第\ref{chap:world_knowledge}章
（推理极端）的工作，三者共同覆盖数据能力光谱的两极与中段，
形成对 Auto-Evol 框架可迁移性的完整证据链。
```

**收益**：直接消除审稿人"GUI CUA 是 GUI 类内迁移"的质疑。

因此，Auto-Evol 在本论文中具有\textbf{双重定位}：（i）作为
