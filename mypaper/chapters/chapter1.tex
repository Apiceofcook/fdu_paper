\section{研究背景}

多模态大语言模型（Multimodal Large Language Model, MLLM）近年来在视觉理解与语言生成方面取得显著进展\citep{openai2024gpt4o,team2023gemini,bai2025qwen25vl,liu2024visual}，并逐步从通用图文理解走向真实应用形态的智能体（Agent）与复杂推理任务\citep{wu2024osatlas,xie2024osworld,llmguiaentsurvey2024}。在这一阶段，模型能力的上限越来越受制于训练数据的质量、对齐与推理密度，而不仅仅是数据规模：互联网抓取的图文对普遍存在噪声大、语义对齐弱、图像质量参差不齐等问题\citep{schuhmann2022laion5b,byeon2022coyo,hessel2021clipscore}；人工标注虽然可靠，但成本高且难以覆盖长尾场景、复杂交互形态与多步推理链路\citep{wang2023selfinstruct,mukherjee2023orca}。与此同时，模型在真实落地任务中暴露出的误差模式往往具有“结构性”：例如对小目标与文字细节不稳定\citep{liu2024seeclick,du2020ppocr}、对视觉证据与语言描述的绑定松散\citep{li2023pope}、对需要先识别再推断的任务易出现短路映射或幻觉\citep{marino2019okvqa,zhang2023multimodalcot}。这些结构性误差表明，仅靠扩规模已经难以系统性地提升模型在关键能力维度上的表现\citep{chen2023sharegpt4v,xu2024mmevol,liu2025synthvlm}——数据质量正在取代数据规模成为多模态模型的能力瓶颈。

针对这一瓶颈，本文的核心主张是：多模态数据生产不应被视为“生成一些图文/问答对”的单步过程，而应被组织为一个面向能力提升的闭环系统——以可控、可迭代、可验证的方式持续产出高信息密度、高对齐度与高推理密度的训练信号。该系统需同时回应模型的三类基础能力——感知（看得清、定位稳）、理解（看得懂、绑得牢）与推理（想得全、链得通），并通过数据源接入 $\rightarrow$ 结构化初始化 $\rightarrow$ 质量过滤 $\rightarrow$ 任务原子化生成 $\rightarrow$ 数据增强 $\rightarrow$ 多维校验 $\rightarrow$ 失败回流的全链路前置约束训练信号质量。换言之，本文要把以往“零散的一次性合成”升级为“闭环可迭代的合成系统”。

要验证上述主张，本文不选择“在通用图文任务上做小幅改进”的常规路线，而是选择\textbf{多模态数据能力光谱的两端场景}作为实证支点，使共通的数据工程骨架在两端之间自然涌现（如图\ref{fig:overview}所示）。其中，\textbf{感知端}对应面向图形用户界面（Graphical User Interface, GUI）的高精度可执行监督（第\ref{chap:gui}章）：GUI 任务（涵盖移动端与桌面端用户界面）以控件密集、文字细小、状态易变为特征\citep{deka2017rico,gao2024mobileviews,liu2024seeclick}，其监督必须细到像素、对到字段、绑到状态——模型需在指代识别（Referring）与视觉定位（Grounding）等任务中输出可执行的目标位置，因此构成数据能力光谱的“高精度、低知识、强可执行”一端\citep{li2022clay,du2020ppocr,guicourse2024,liu2025uie2isynth,guiworld2024}。\textbf{推理端}则对应面向世界知识的可验证对齐与过程推理（第\ref{chap:world_knowledge}章）：世界知识（World Knowledge）任务要求模型把图像中的具体实例锚定到知识空间的抽象实体与事实\citep{marino2019okvqa,schwenk2022aokvqa,chen2023infoseek}，并在多跳条件约束下完成“先识别 $\rightarrow$ 再检索 $\rightarrow$ 再筛选”的推理链路\citep{chang2022webqa,lewis2020rag,yao2023react}；其数据工程的关键不是像素级精度，而是语义级可验证对齐与过程性监督——训练样本必须可核验、答案必须唯一、推理链路必须显式\citep{li2023pope,wei2024simpleqa,wei2022chain,zhang2023multimodalcot}，因此构成光谱的“高知识、需推理、弱像素约束”一端。两端的策略性互补使得二者并非“两件不相关的事”，而是把多模态数据需求拉到了能力光谱的两端：GUI 解决“看得准、点得稳”，世界知识解决“懂得对、推得通”。在两端的真实工程实践中，数据源组织、结构化初始化、任务分解与生成、增强/过滤/多维校验、失败回流与闭环迭代等模块以高度一致的形态反复出现，这正是本文得以将其抽象为统一框架的实证基础。

除两端之外，许多真实任务同时需要感知与推理两类能力的协同——例如计算机使用智能体（Computer Use Agent, CUA）场景下的 GUI 任务（GUI CUA），其完整动作链同时要求模型看清当前界面控件状态（感知）、规划多步操作序列（推理）与跟踪动态状态转移三者协同，因而处于数据能力光谱的\textbf{综合中段}。基于两端的工程实践与共通模式归纳，本文在第\ref{chap:gui}章与第\ref{chap:world_knowledge}章分别给出 GUI 与世界知识两条数据工程主线，并在第\ref{chap:framework}章进一步将二者共通的骨架抽象为\textbf{Auto-Evol 多模态数据合成框架}；在框架抽象之上，本文还将该框架实例化到 GUI CUA 综合中段场景，依托 OSWorld 评测体系\citep{xie2024osworld}构建可验证任务合成的工程系统，并通过端到端“合成任务$\rightarrow$轨迹采集$\rightarrow$单步拆分$\rightarrow$监督微调（Supervised Fine-Tuning, SFT）”实验提供 Qwen3-VL-Think 在 OSWorld LibreOffice 三个领域上 40.8\%$\rightarrow$61.4\%（+20.6 pt）的量化证据，与 EvoCUA\citep{xue2026evocua}等近期工作形成互补。图\ref{fig:overview}给出了本文研究问题、两端主线与统一框架之间的关系，全文章节按“两端实证 $\rightarrow$ 共通抽象 $\rightarrow$ 综合中段端到端验证”的顺序展开。

\section{主要贡献}

本文围绕“多模态数据合成框架”这一主线，沿数据能力光谱的三个代表性位置（感知端 / 推理端 / 综合中段）展开“两端实证 $\rightarrow$ 共通抽象 $\rightarrow$ 综合中段端到端验证”的研究路径，主要贡献总结为三点：
\begin{itemize}
  \item 感知端：面向 GUI 的高质量数据工程与可执行定位能力提升方案（精细但强约束的合成/标注范式）：针对 GUI“控件密集、文字细小、状态易变”的特征，构建多源融合的数据 Pipeline 与结构化监督信号（bbox / OCR / 关系 / 状态），并结合高分辨率感知与训练策略提升 Referring 与 Grounding 两项核心能力；该部分更偏向“相对原始但精细”的数据合成与标注工程，为后续更复杂任务的监督设计提供可复用的监督原子与质控方法（如表\ref{tab:gui_data_ablation}、表\ref{tab:gui_grounding}与表\ref{tab:gui_referring}所示）。
  \item 推理端：面向世界知识的可控对齐与推理贯通数据体系（增强与反向对齐的更先进合成范式）：构建覆盖广、可扩展的世界知识类别框架，并设计“词条$\rightarrow$图片$\rightarrow$caption$\rightarrow$相关性过滤$\rightarrow$三类QA”的数据 Pipeline；引入数据增强与从答案出发的反向对齐流程，提升“视觉证据$\leftrightarrow$知识事实”的可验证性；进一步通过带推理过程（Think/CoT）的 FinalQA 缓解短路映射与任务冲突，专项 SFT 设置下推理指标相对 Qwen2.5-VL-7B 显著提升（表\ref{tab:wk_think_improve}，F1\_Final +11.9 pt），最终在 Chinese SimpleVQA 与 SimpleVQA 上取得有竞争力的整体结果（表\ref{tab:wk_final_chinese}与表\ref{tab:wk_final_english}）。
  \item 共通抽象 + 综合中段端到端验证：Auto-Evol 多模态数据合成框架及其 GUI CUA 实例化：在两端数据合成范式的差异与共通点之上，抽象出一套面向能力提升的通用数据合成流程，统一刻画数据源接入、结构化初始化、质量过滤、任务路由与原子问题生成、数据增强、多维校验、失败回流重写共七个关键模块，使高信息密度、高对齐度与高推理密度的数据能够被稳定、迭代地产出与复用（对应第\ref{chap:framework}章的整体框架与模块设计）；进一步将该框架实例化到综合中段——GUI 计算机使用智能体（Computer Use Agent, CUA）场景（多步操作链 + 动态状态跟踪），依托 OSWorld\citep{xie2024osworld}评测体系，在 LibreOffice 三个领域（Calc/\allowbreak Impress/\allowbreak Writer）上完成端到端验证，并已沿用同一套 Pipeline 骨架向 VSCode、Chrome 等扩展领域拓展，与近期 EvoCUA\citep{xue2026evocua}等代表性工作形成互补；端到端训练实验进一步证实其有效性——基于本框架合成的 900 任务、723 成功轨迹与 3 万条单步训练数据，将 Qwen3-VL-Think 在 OSWorld LibreOffice 三个领域上的总体准确率由\textbf{40.8\%}提升至\textbf{61.4\%}（绝对增益\textbf{+20.6 pt}，详见\ref{sec:auto_evol_gui_cua}节与表\ref{tab:gui_cua_train_result}）。
\end{itemize}

\section{论文组织结构}

本文的组织结构如下：

第一章（绪论）介绍研究背景、问题动机与本文的主要贡献，并给出全文组织结构。

第二章（相关工作）回顾视觉-语言模型与多模态大模型的发展脉络，以及GUI理解、世界知识增强与多模态数据合成相关研究，为本文方法设计提供背景支撑。

第三章（面向GUI的能力提升 —— 感知端实证）围绕Referring与Grounding两项核心能力，给出GUI场景的数据工程Pipeline、结构化监督设计与训练策略（如高分辨率感知与双阶段混合微调），并通过控件级评测验证方法有效性（第\ref{chap:gui}章）。该章对应数据能力光谱的感知端，聚焦“精细但强约束”的数据合成与标注流程，为后续章节的更复杂合成提供方法基座。

第四章（世界知识能力提升 —— 推理端实证）构建世界知识类别框架与端到端数据 Pipeline，提出 RecQA/\allowbreak KnowQA/\allowbreak FinalQA 的任务分解，并通过引入数据增强、反向对齐与 Think/CoT 等过程性监督提升“先识别再推理”的世界知识推理能力（第\ref{chap:world_knowledge}章）。该章对应数据能力光谱的推理端，相较 GUI 进一步强调对齐可信与推理贯通，为统一框架抽象提供更丰富的模块形态。

第五章（多模态数据合成框架 —— 共通抽象 + 综合中段端到端验证）在第三、四章两类数据合成范式的对比与互补基础上，提炼共通机制与可改进方向，进一步抽象提出 Auto-Evol 多模态数据合成框架，系统阐述闭环 Pipeline 及其关键模块，并结合实验现象对核心设计进行归因式验证；在框架抽象之上，本章还将 Auto-Evol 实例化到综合中段的 GUI CUA 场景，基于 OSWorld 评测体系\citep{xie2024osworld}构建可验证任务合成的工程系统，在 LibreOffice 三个领域上完成端到端验证，并已沿用同一套 Pipeline 骨架向 VSCode、Chrome 等扩展领域拓展，通过“合成任务$\rightarrow$轨迹采集$\rightarrow$单步拆分$\rightarrow$SFT”的端到端实验给出量化证据（Qwen3-VL-Think 总体准确率 +20.6 pt），与 EvoCUA\citep{xue2026evocua}等代表性工作形成方法学层面的互补。

第六章（结论）总结全文工作与主要结论，分析研究不足，并展望未来研究方向。
