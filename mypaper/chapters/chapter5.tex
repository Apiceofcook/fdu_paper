\chapter{世界知识能力提升方案}
\label{chap:world_knowledge}

延续第\ref{chap:gui}章在\textbf{感知端}沉淀的“高精度像素级监督”方法基座，本章把研究视角从“看得清、定位稳”切换到“懂得对、推得通”——也即数据能力光谱另一端的\textbf{推理端实证}。如果说 GUI 任务考验的是模型对可见证据的精确绑定，那么世界知识任务则要求模型在视觉证据之外进一步引入外部知识，并在多步条件约束下完成可验证的推理。本章作为“两端实证”路线的另一极，在数据组织、监督形态与质控目标上与第\ref{chap:gui}章形成显著互补：前者强调“几何精度 + 状态绑定”，本章强调“可验证对齐 + 过程性监督”。两章共同为后续第\ref{chap:framework}章 Auto-Evol 统一框架的抽象提供互补的实证基础——其差异正是框架“共通骨架”得以涌现的前提，而其共通的工程模块（结构化初始化、相关性过滤、原子化任务分解、多维校验、失败回流）则将在第\ref{chap:framework}章被显式抽象为可跨任务迁移的方法学。

\section{任务定义与核心挑战}
当多模态模型从“描述图像”走向“理解图像背后的事实、概念与关系”时，世界知识便成为关键瓶颈：模型不仅要识别画面中的具体实例，还要将其锚定到外部知识空间中的抽象事实并完成多步推理。本节先给出本文对世界知识能力的定义并以一个直观案例阐释其与“纯视觉描述”的差异，再归纳世界知识注入在实践中的三大核心困境，并据此明确本章的研究目标与方法路线。

\subsection{任务定义：从“看见”到“理解”}
本文将\textbf{世界知识}（World Knowledge）定义为对物理世界、社会文化、历史事件、科学技术等领域的事实、概念、关系与常识的综合掌握，其本质是一个庞大且交织的知识网络。相比第\ref{chap:gui}章关注的“可见语义与几何定位”，世界知识能力要求模型在视觉证据之外进一步引入外部知识，并在“识别--调用知识--条件推断”的链路上稳定输出。

图\ref{fig:wk_case}给出了一个直观的对比案例：对于经典电影《泰坦尼克号》的标志性场景，缺乏世界知识的模型仅能给出浅层描述——“一个男人和一个女人站在船头”；而具备世界知识的模型则能识别出这是 1997 年上映的电影《泰坦尼克号》，由詹姆斯·卡梅隆执导，主演为莱昂纳多·迪卡普里奥与凯特·温斯莱特，并进一步理解这一场景描绘了主角杰克与露丝在船头“飞翔”的浪漫时刻，以及该影片在全球取得的商业成功与文化影响力。这种从“看见”到“理解”的跃迁，正是世界知识赋予模型的核心能力，也是本章后续数据合成与训练优化的直接监督目标。

\subsection{三大核心困境}
提升 VLM 的世界知识能力并非简单“增加数据量”即可解决，世界知识注入在实践中往往同时受到三大困境的制约。\textbf{困境一是知识整合与收集（Integration）}：目前的世界知识通常存在于庞大的文本语料库或结构化知识图谱中，知识源虽然丰富，但要从中抽取并组织成可被模型学习的训练样本并不容易。其难点在于知识高度分散且表达形式异构（不同来源对同一实体的称呼、粒度与侧重点不一致），同时存在噪声与时效性差异；直接“搬运知识”难以保证与视觉内容可验证对应，导致样本在训练时容易引入错误监督或不可学习信号。\textbf{困境二是视觉与语言对齐（Alignment）}：大语言模型往往已具备一定的世界知识能力，但视觉侧未必能将图像中的具体实例（Specific Instance）与文本知识中的抽象描述（Abstract Description）精确关联。例如，图像中出现一只特定的鸟，文本知识可能包含该鸟类的学名、习性与分布范围，但模型难以将这些抽象属性稳健地“落到”当前图像实例上，从而出现“知道但看不出来”或“看出来但说不对”的错配；同一实体在不同视角、光照、遮挡或风格化图像中呈现的显著差异，也会放大对齐难度并影响泛化能力。\textbf{困境三是多跳推理能力（Reasoning）}：许多复杂世界知识问题需要模型进行多步推理，将多个知识点链接后再得出结论。例如，回答“图中这位导演拍摄的、获得奥斯卡最佳影片的电影是哪部？”需要模型先识别图中人物为某位导演，再检索或回忆其作品列表，最后按“获奥斯卡最佳影片”条件进行筛选得到唯一答案。该过程要求模型同时具备稳定的实体识别、可控的知识调用以及可执行的条件推断链路，对当前 VLM 仍是显著挑战。

\subsection{研究目标与本章路线}
针对上述三大困境，本章在数据工程层面给出系统性应对：以\textbf{知识类别框架}约束知识收集的覆盖与边界（应对 Integration），以\textbf{caption 中间表征 + 相关性过滤}建立稳健的视觉--知识锚点（应对 Alignment），以\textbf{RecQA / KnowQA / FinalQA 三类任务分解 + Think/CoT 过程监督}显式拆解并训练多步推理链路（应对 Reasoning）。本章后续将依次展开知识类别框架、世界知识数据 Pipeline、训练与实验，并在 Chinese SimpleVQA 与 SimpleVQA 等基准上给出量化验证；本章沉淀的可验证对齐、过程性推理监督与中间表征 caption 等模块，将与第\ref{chap:gui}章在感知端的实践共同构成第\ref{chap:framework}章 Auto-Evol 统一框架的实证基础。

\section{知识类别框架}
世界知识增强的首要前提，是建立一个可覆盖、可扩展、可操作的知识类别框架。若缺乏统一的类别坐标系，世界知识将以“零散事实”的形式分布在不同来源中，不仅难以进行系统性采样与补全，也难以在训练与评测中对模型能力进行可解释的归因分析。因此，本文构建分层分类体系，包含7个大类与40个子类（如图\ref{fig:wk_class}所示），用于约束数据构造过程并为后续框架化的数据Pipeline提供统一接口。

\begin{figure}[!htbp]
  \centering
  \includegraphics[width=0.9\linewidth]{figures/chapter5/wk_class.png}
  \caption{世界知识类别框架（7个大类与40个子类）。}
  \label{fig:wk_class}
\end{figure}

类别制定的作用与必要性主要体现在三方面：一是\textbf{指导词条生成与采样}，在每个子类的定义约束下，词条生成能够被限定在明确语义边界内，避免“概念混淆”（如将作品名误作人物名）与“粒度漂移”（如将系列与单部作品混用），从而提升词条集合的可控性与可复用性；二是\textbf{支持长尾覆盖与迭代补全}，按子类统计实体与样本分布可显式暴露稀缺类别与薄弱子类，便于后续定向补齐与均衡采样；三是\textbf{作为训练/评测的统计维度}，类别标签为分析不同知识域的对齐难度、误差模式与泛化瓶颈提供了可解释的分组依据。

为保证后续“词条生成$\rightarrow$图片收集$\rightarrow$标注与QA构造”的一致性，本文为每个大类与子类均给出可操作的边界定义，定义内容包括：覆盖范围（该类包含哪些实体/概念）、排除规则（易混淆但不属于该类的情况）、命名规范（中英文/别名/译名的处理方式）以及典型示例（用于提示生成与校验）。例如，建筑景观/地标建筑强调“可定位的实体建筑与场所”，并排除“抽象建筑风格”；文化娱乐/电影以“独立作品”为基本粒度，区分系列名与单部片名；品牌商标/商业Logo强调“可识别的品牌标记”，并区分公司主体与产品线名称。

在该框架下，代表性大类如下：
\begin{itemize}
  \item 自然景观：自然形成的地理实体与景观要素，强调可定位与可辨识性（如河流、山脉、森林、沙漠等）。
  \item 生物：具有明确物种/类群归属的生命体实体，强调可用学名/别名统一归并（如知名动物、植物、真菌等）。
  \item 建筑景观：人造建成环境中的可识别实体，强调“具体建筑/场所”而非抽象风格（如地标建筑、宗教场所等）。
  \item 人物：具有可追溯身份的真实人物实体，强调同名消歧与多语别名对齐（如政治人物、演艺明星、历史名人等）。
  \item 品牌商标：可被视觉识别的品牌标记与商业符号，强调品牌与产品的边界区分（如商业Logo、产品包装等）。
  \item 文化娱乐：文化作品及其衍生实体，强调作品粒度与系列关系的规范化（如电影、游戏、动漫、书籍等）。
  \item 科学技术：科技相关的可识别对象或现象，强调术语标准化与概念边界（如特定设备、科学现象等）。
\end{itemize}
该框架为后续章节中的词条生成、图片收集与QA构造提供了稳定、可复用的“坐标系”，使世界知识数据构造从零散经验转为可控流程，并为后续框架的建立与扩展提供结构化支撑。

\subsection{词条生成与图片收集：从知识域到视觉证据}
对应图\ref{fig:wk_data_pipeline}中的“词条生成和图片收集”环节，本文首先在前述知识类别框架的约束下，为每个子类生成可控的词条集合，并围绕词条自动化收集图片，以形成“实体$\leftrightarrow$视觉证据”的锚点，为后续图文对齐与知识学习打下基础。具体流程包括三步：首先进行\textbf{类别制定}，基于前述分类体系的定义边界确定每个子类的覆盖范围与排除规则，从源头保证后续词条生成与样本采样的语义一致性与可追溯性；接着进行\textbf{词条生成}，采用大模型依据类别/子类定义生成“最热门、最具公众关注度”的核心词条（每类约 150$\sim$200 个）以覆盖主流高频知识，并由人工补充新近出现或相对冷门但具研究价值的词条，以提升长尾覆盖并缓解仅学习头部概念带来的偏置；最后进行\textbf{图片收集}，针对每个词条实现一个自动化的图片收集 agent 脚本，调用 Google 图片搜索抓取该词条返回结果中的前 100$\sim$500 张图片，将抽象词条落到具体视觉实例上，并保留来源、分辨率、时间等元信息以支持去重与质量追踪。
在这一阶段，数据工程的目标是“实体可控”与“图像高质量”：实体可控保证知识监督可追溯，图像高质量保证视觉侧对齐不被噪声主导。

\subsection{图片Caption生成：融合视觉描述与知识背景}
对应图\ref{fig:wk_data_pipeline}中的“图片CAPTION生成”环节，本文为每张自动抓取的图片生成结构化caption，其作用不仅是“生成更丰富的描述”，更是为后续多个关键环节提供可依赖的中间表征：(1) 图文相关性过滤需要caption帮助模型判断图片是否真的与词条匹配；(2) 知识要素提取可从caption中抽取实体属性、别名与背景事实；(3) QA对生成可将caption作为问题构造与答案验证的上下文依据。

尤其在相关性过滤场景下，由于图片是自动抓取的，实际会混入与词条无关的图片（例如同名歧义、检索噪声、相似外观实体等）。仅依赖视觉模型直接判别相关性容易受限于大模型自身的识别能力与先验偏差，因此本文将caption与词条知识一并提供给过滤模型作为判据，从而提升过滤的稳健性与可解释性。

图\ref{fig:wk_caption_case}给出了caption数据的一个示例。可以看到，caption不仅描述了画面中的关键视觉元素（两名士兵、英军制服、草地与田野等），还补充了与该视觉内容强相关的背景知识（电影名称、上映年份、导演、拍摄手法与剧情要点）。这类“视觉描述+背景知识”的融合表达，一方面为后续相关性过滤提供了更可验证的判断依据，另一方面也为知识要素提取与QA构造提供了可复用的文本上下文。

\subsection{图文相关性过滤：保证视觉-知识对齐质量}
对应图\ref{fig:wk_data_pipeline}中的“图文相关性过滤”环节，本文通过两步保证数据质量。其一是\textbf{相关性分数制定}：采用大模型进行判别，并设置 1$\sim$5 的离散相关性分数以刻画“图片$\leftrightarrow$词条”的匹配强度——5 分表示完全相关（图片直接包含标签内容），4 分表示高度相关（作品/组成部分等紧密关系），3 分表示中等相关（可联想但不直接对应），2 分表示低度相关（需较强推理才能建立联系），1 分表示完全不相关；模型在输出分数时同时给出简要理由，并采用固定格式（如“相关性分数：[分数]”）便于程序解析与自动化处理。其二是\textbf{阈值化过滤与尽可能保留}：考虑到大模型判别仍存在误差，本文并非“一刀切”地仅保留最高分样本，而是通过设定分数阈值与抽样复核策略，尽可能保留潜在相关图片（如 4 分、部分 3 分样本），以在覆盖率与噪声控制之间取得平衡。过滤后的样本将进入后续 QA 构造，从源头降低“错图错标”导致的对齐噪声。

\paragraph{过滤效果对比与人工评估。}
为量化“相关性分数”策略对数据保留率与幻觉噪声的影响，本文从原始抓取结果中随机抽取2000条“图片--词条”样本进行对比实验。若不设置相关性分数、仅让模型输出“相关/不相关”的二分类判断，则最终只能保留约1009条数据；而在制定1$\sim$5相关性分数并保留3分及以上样本后，可保留约1511条数据，显著提高可用数据覆盖。

可以看到，相关性分数的制定在保留更多数据的同时，“几乎无幻觉”样本占比也显著上升，并有效降低“部分/大部分幻觉”样本比例。这说明分数化判别相比二分类更能缓解因大模型自身不认识或误识别带来的误判与幻觉噪声，从而在覆盖率与对齐质量之间取得更优平衡。

\subsection{QA对生成：从描述到三元组任务}
对应图\ref{fig:wk_data_pipeline}中的“QA对生成”环节，为了解耦感知与推理，本文构造三类互补问答对：
\begin{itemize}
  \item RecQA（Recognition QA）：对应“模型看见图片”的能力，问题围绕“这是谁/这是什么/来自哪里”等识别任务，答案为实体或关键属性。其目标是将视觉特征稳定锚定到词条实体，解决“看到但叫不出名字”的问题。在生成时，模型输入包括图片、图片对应的caption、目标词条以及词条所属类别，用于约束识别问题的指向性与答案空间。
  \item KnowQA（Knowledge QA）：对应“模型知道关于该实体的世界知识”的能力，问题强调外部知识（历史、文化、科学属性等），形式上可不依赖视觉信息，但与图片实体强相关。其目标是向模型注入可泛化的背景事实，解决“认识了但不了解”的问题。在生成时，模型输入为RecQA问答对与caption，并要求其基于RecQA的答案（已识别实体）提出相关知识问题，从而将知识提问锚定在正确实体上。
  \item FinalQA（Reasoning QA）：对应“模型理解图片并能调用知识推理”的能力，问题需要“先识别再用知识推理”，可是一跳或多跳链路（如识别实体$\rightarrow$回忆知识$\rightarrow$条件筛选）。其目标是打通RecQA与KnowQA形成的知识链路，推动模型从“描述/识别”走向“解释/推断”。在生成时，模型输入同时包含RecQA与KnowQA两类QA，引导其融合“识别结论+知识要点”构造最终问题与答案，显式贯通两阶段信息。
\end{itemize}

三类QA分别对应不同能力层次：RecQA偏感知/识别，KnowQA偏理解/知识，FinalQA偏推理/筛选。这种拆分避免模型直接学习“图像$\rightarrow$最终答案”的捷径，从而提升泛化与可解释性。

图\ref{fig:wk_qa_case}展示了三类QA在同一实体上的组织方式。RecQA首先要求模型从图像中识别出“戴着条纹围巾的光头男性角色”为格鲁（Gru）；KnowQA进一步询问与该实体相关、但必须依赖外部知识才能回答的问题（例如《神偷奶爸》系列的制作公司）；FinalQA则将二者合并为一步推理问题，使模型必须先完成识别，再调用知识得到最终答案。此外，为了促进可解释推理与避免“直接背答案”，本文还构造带有简要推理过程的FinalQA（FinalQA with CoT），要求模型先给出识别结论，再给出问题答案。

\subsection{QA对质量过滤：确保训练数据可靠性}
对应图\ref{fig:wk_data_pipeline}中的“QA对质量过滤”环节，本文采用多级质控保证知识可靠与对齐有效。\textbf{规则约束与质量分数制定}是第一步：本文使用大模型对“问题--答案”对进行规则校验，重点约束包括问题必须同时依赖图像信息与外部知识（既不能纯靠知识回答，也不能纯靠图像即可回答）、问题应当客观明确且无歧义、答案必须唯一且不随时间变化、避免一个问题中同时询问两个子问题等；基于满足程度给出 1$\sim$3 的质量分数，3 分表示完全合格，2 分表示勉强合格但必须满足“唯一答案/时效稳定/单问题”这些关键约束，1 分表示不合格；模型输出时给出简要理由并采用固定格式（如“合格分数：[分数]”）便于解析。\textbf{低质量过滤与回收}是第二步：对低分样本进行过滤或回收重写，重点剔除多答案、表述模糊、主观化或时效性强的问题，从而保证训练信号的可学习性与评测的一致性。\textbf{评测基准去重}是第三步：为避免训练数据与评测基准（如 Chinese SimpleVQA、SimpleVQA）在图像层面发生重叠导致评测泄漏，本文在构造训练集时对评测基准中的图片进行 hash 去重——对训练集与评测集图片分别计算感知哈希（perceptual hash，如 pHash/dHash 等）并以哈希值作为指纹建立索引，若训练样本图片与评测基准图片哈希完全一致则直接从训练集中剔除；同时可进一步基于哈希间的汉明距离进行相似度判别，在距离小于阈值时视为近重复（如压缩、裁剪、分辨率变化导致的轻微差异）并一并过滤，从源头保证评测的独立性与结论可信度。

\section{训练与实验：从数据类型消融到CoT对齐}
本节将训练策略与实验分析合并阐述：首先通过消融实验验证不同数据类型对世界知识能力的影响；随后针对推理指标“增益不显著甚至下降”的现象，引入带推理过程的Think/CoT数据并扩充数据分布，给出改进后的结果；最后报告在Chinese SimpleVQA与SimpleVQA上的最终性能，并分析与强基线之间的差距。

\subsection{多阶段、多来源数据构建}
训练过程中，本文采用多批次策略逐步扩充数据分布。\textbf{Batch 1（Part1）}使用最强模型构建第一批数据，确保高精度与高一致性；\textbf{Batch 2 及后续（Part12、Part123）}则引入不同模型与更多未见词条扩充数据分布，降低单一模型偏置并提升长尾覆盖。

同时，在同一批次的数据构造Pipeline中，本文也会针对不同环节的侧重点选用不同模型，以进一步降低单一模型带来的偏置风险：词条生产依赖知识覆盖更强的文本模型\texttt{gpt5}；caption生成使用当时更强的多模态模型\texttt{Gemini-2.5-pro}与\texttt{gpt-4o}以提升视觉描述与背景知识补全质量；后续RecQA/\allowbreak KnowQA/\allowbreak FinalQA的生成更偏向于从caption中抽取与融合知识，因而采用指令遵循更强且生成效率更高的\texttt{Gemini-2.5-flash}以提升规模化产出稳定性。

\subsection{实验一：数据类型消融与冲突分析}
本实验的目的在于确定不同数据类型对世界知识能力是否具有正向影响，并定位可能的任务冲突。评测指标包括识别侧（Correct、Accuracy、F1）与推理侧（Correct、Accuracy、F1），分别对应Recognition与Final两类任务。

实验结果如表\ref{tab:wk_ablation_part1}所示，可以得到以下结论：
\begin{itemize}
  \item 与强基线仍有差距：尽管数据增强带来提升，但与Qwen2.5-VL-7B相比\citep{bai2025qwen25vl}，各项指标仍存在明显差距，说明世界知识能力提升仍受限于模型容量、数据覆盖与对齐质量等因素。
  \item Image Caption对识别有正向作用：加入caption类数据能为识别任务提供更稳定的视觉--文本锚点，使recognition相关指标相对base获得稳定提升（F1\_Rec从28.1提升至31.4--33.1）。
  \item 仅监督最终答案的FinalQA未观察到稳定推理增益：在不引入显式推理过程的Direct Answer形式下，加入FinalQA的两个配置（all、RKFQA）相较base在final指标上分别为$-0.7$与$+0.1$，未呈现稳定增益；同时，移除FinalQA的RKQA配置出现更明显的回落（F1\_Final由37.0降至35.2），提示在没有显式推理监督的情况下，单纯调整RecQA/KnowQA/FinalQA组合难以稳定提升推理能力，这一现象指向“需要更显式过程监督”的改进方向（详见实验二）。
  \item 短路映射风险与任务冲突：当FinalQA仅强调“直达最终答案”时，模型容易学习“图像特征$\rightarrow$答案”的短路映射，与RecQA对实体识别与稳健锚定的目标存在潜在冲突；同时识别不稳又会反过来限制FinalQA的推理上限。这一假设也在实验二（引入Think/CoT后final指标显著回升）中得到进一步印证。
\end{itemize}

\subsection{实验二：引入Think/CoT与数据扩充的改进效果}
由于实验一中推理指标不升反降，我们进一步验证推理过程监督的作用。核心观察是：当FinalQA仅监督最终答案时，模型更容易“记答案”；而当FinalQA要求输出简要推理过程（Think/CoT）\citep{wei2022chain}，模型被迫先完成识别再调用知识，从而更有效地提升final相关指标。

基于这一发现，本文采取四项改进思路并在表\ref{tab:wk_think_improve}中给出结果。其一是\textbf{保留所有类型数据}：同时保留 caption、RecQA、KnowQA、FinalQA 等多种数据，以维持“视觉锚定+知识注入+推理贯通”的能力闭环；其二是\textbf{扩充未见词条}：继续扩充模型未见过的新词条与长尾实体，提升泛化能力与覆盖面；其三是\textbf{FinalQA 增加 CoT 过程}：将 FinalQA 从 Direct Answer 升级为带简要推理过程的形式，使模型学习“先识别再推理”的过程性能力；其四是\textbf{增加 KnowQA 与 FinalQA 密度}：同一张图片可生成多个 KnowQA 与 FinalQA 样本，提高知识链路覆盖与训练信号密度。

\section{本章小结}
本章围绕视觉语言模型在世界知识理解上的不足，系统构建了面向世界知识增强的数据体系与训练框架，为后续统一框架的提出提供了可复用的工程化基础。本文的主要贡献与创新点可概括为：
\begin{itemize}
  \item 提出可操作的世界知识类别框架：构建7个大类、40个子类的分层分类体系，并强调每个类别/子类的覆盖范围、排除规则与命名规范，从而将“世界知识”从零散事实组织为可采样、可统计、可扩展的结构化坐标系，直接服务于后续词条生成与长尾覆盖。
  \item 给出端到端的世界知识数据构造Pipeline：围绕“词条生成$\rightarrow$自动化图片收集$\rightarrow$caption生成$\rightarrow$相关性过滤$\rightarrow$QA对生成$\rightarrow$质量过滤”建立稳定Pipeline。尤其通过caption作为中间表征支撑图文相关性判别，并引入1$\sim$5分相关性评分机制，在覆盖率与噪声控制之间取得更稳健的平衡。
  \item 设计RecQA/\allowbreak KnowQA/\allowbreak FinalQA的三元组任务分解并引入CoT监督：从“看见$\rightarrow$知道$\rightarrow$理解并推理”的能力递进出发，将感知、知识与推理解耦为三类互补监督信号，避免模型学习“图像$\rightarrow$答案”的捷径；进一步将FinalQA升级为带简要推理过程的FinalQA with CoT，使模型学习可迁移的推理链路而非记忆答案。
  \item 通过消融实验揭示冲突并验证改进有效性：实验表明caption对识别指标具有稳定增益，而仅提供Direct Answer形式的FinalQA对推理指标提升不显著甚至下降，反映出FinalQA与RecQA在训练中存在短路映射带来的冲突；引入Think/CoT并扩充未见词条与多问一图数据后，final相关指标得到显著改善，并在Chinese SimpleVQA与SimpleVQA上取得具有竞争力的最终结果。
\end{itemize}

对比第\ref{chap:gui}章以高精度、可执行、强约束的像素级监督为核心、侧重“看得准、点得稳”的数据工程范式，本章进一步将监督重心推进到知识级对齐可信度与推理过程可学习：通过知识类别框架与反向对齐思路实现可控覆盖，以caption作为可依赖的中间表征支撑相关性分数过滤与对齐校验，并以RecQA/\allowbreak KnowQA/\allowbreak FinalQA（及Think/CoT）将“先识别再推理”的链路显式化，从而在保留更多数据的同时抑制幻觉与短路学习。上述实践不仅丰富了相较GUI更“先进”的增强、过滤与过程性约束模块，也沉淀出跨任务可复用的共通骨架（数据源组织、结构化初始化、任务分解与生成、增强/过滤与多维校验、回流迭代）。基于这些共通结构，下一章将进一步抽象并系统化提出完整的Auto-Evol多模态数据合成框架，将零散的一次性合成升级为可路由、可评测、可闭环迭代的数据合成系统；并在框架抽象之上，将Auto-Evol进一步实例化到GUI计算机使用智能体（Computer Use Agent, CUA）场景，依托OSWorld评测体系\citep{xie2024osworld}构建面向\textbf{可验证任务合成}的工程系统，跨LibreOffice三个domain（Calc/\allowbreak Impress/\allowbreak Writer）与VSCode、Chrome等扩展domain验证框架在“看--懂--做”闭环下的可迁移性，并与EvoCUA\citep{xue2026evocua}等代表性工作形成方法学层面的互补（详见第\ref{sec:auto_evol_gui_cua}节）。
